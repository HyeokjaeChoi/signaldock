Notes:
- Stripe runs 4 GitHub workflows. Its `ci_scripts/` (SPM warning check, DocC, SwiftLint) are not wired to those workflows in the repo, so the caller is not confirmed.
- Datadog CI is GitLab (`.gitlab-ci.yml`). Braze has no workflow files in its repo.
- Warnings as errors: not found in any repo. Datadog sets `SWIFT_TREAT_WARNINGS_AS_ERRORS = NO` in `tools/repo-setup/Base.ci.xcconfig.src`. Stripe fails on SPM warnings (`ci_scripts/check_spm_warnings.rb`). Mixpanel and Amplitude run `pod lib lint --allow-warnings`. PostHog runs `swiftlint` without `--strict`, but its `.swiftlint.yml` makes violations errors.
- Main Thread Checker: not found in any repo.
- Firebase pins SwiftFormat 0.55.5 in `Mintfile`. `setup_check.sh` runs `mint bootstrap`. The format invocation inside `check.sh` is not confirmed.
- Sentry sanitizers run only on the thread-inspection harness in `test-v10.yml`, not on the SDK unit test plans.
- Sentry has no `.podspec` in its repo tree.

Gates used by most vendors (count of ✓ out of 9, ✗ and ? excluded):
1. Privacy manifest bundled in the package: 8/9. Repo CI validates it: 0/9.
2. Lint/format job: 7/9 (SwiftLint or SwiftFormat).
3. Multi-platform test matrix (iOS, macOS, tvOS, watchOS or visionOS): 7/9.
4. Package build for SPM or CocoaPods: `pod lib lint` 5/9, SPM build/test 5/9.
5. Public API diff: 5/9.
6. Test-level retry: 3/9 (Sentry, Mixpanel, PostHog). Flaky-test tracking adds PostHog's report step.
7. CodeQL or static analyzer: 3/9 CodeQL (Sentry, Firebase, PostHog), 1/9 `xcodebuild analyze`.
8. Sanitizers: 2/9 (Firebase full, Sentry partial).
9. Single-vendor gates: binary size (Sentry), coverage threshold (Segment), DocC (Stripe), extension-safe build (Firebase Auth), benchmarks (Datadog), dead-code scan (Stripe).
