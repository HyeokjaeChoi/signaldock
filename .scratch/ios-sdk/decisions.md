# iOS SDK grilling log

Working record of owner decisions. The spec (`spec.md`) is the source after it is written.

- 2026-10-26 Scope: next scope is the native iOS SDK (owner choice; research in `.scratch/next-scope/`).
- 2026-10-26 Q1: first iOS release has behavior parity with Android SDK 0.3.0 (owner: "parity로 하라고 그 세션에 전달해줘"). Android-only mechanisms (Baseline Profile, R8, WorkManager) are not ported; iOS equivalents are decided separately.
- 2026-10-26 Q2: platform on the wire = optional event-level `sdkPlatform` enum `android|ios` next to `sdkVersion` (contract 1 additive, server first). Missing → server stores `android`. Kill switch blocks by `(sdkPlatform, sdkVersion)`. Migration adds `sdk_platform` to `events` and `client_reports`. Android SDK sends it from its next version.
- 2026-10-26 Q3: installation ID = UUIDv4 in a file under Application Support `signaldock/`, `isExcludedFromBackup = true`; deleted with the app, so reinstall gives a new ID (ADR-0001). Keychain and IDFV rejected. Verify item: device-to-device transfer does not carry excluded files (primary source).
- 2026-10-26 Q3 known limit: Apple says `isExcludedFromBackup` does not guarantee a file never appears on a restored device, so a restored device can rarely share an installation ID. Decision unchanged; spec records it as a known limit.
- 2026-10-26 Q4: event queue = system SQLite3 C API behind a thin internal wrapper, zero external dependencies. Same queue schema and transaction boundaries as Android Room (ADR-0003, ADR-0006). Versioned SQL migrations; a released migration is frozen (iOS form of ADR-0025, checked by `scripts/check-repo-rules.sh`). Industry: Mixpanel raw SQLite3; Amplitude/Segment/PostHog/RudderStack files (`.scratch/next-scope/ios-sdk-practices.md`).
- 2026-10-26 Q5: delivery = Android foreground rules (20 events or 10 s drain; SDK-persisted retry clock) + one drain on `didEnterBackground` inside `beginBackgroundTask` (expiration cancels the request; queue and transactional ACK keep data) + drain at launch and foreground return when the stored next-attempt time has passed. No BGTaskScheduler (host Info.plist/capability burden; OS-chosen timing; none of 6 surveyed SDKs use it). Platform difference: no periodic background send; events left after a background kill go at next launch.
- 2026-10-26 Q6: iOS 15 minimum; Swift 6 language mode (strict concurrency); public API `async` (1:1 with Kotlin `suspend`); results as Swift `enum`; single sender as an `actor`. No completion-handler or Objective-C API. Owner: no third-party async library; Swift Concurrency only, following best practice; strict unit tests that prove no race conditions.
- 2026-10-26 Q6 tests: Swift 6 compile-time data-race checks; CI unit tests under Thread Sanitizer; deterministic tests with injected clock and transport; no sleep-based timing in tests.
- 2026-10-26 Q7: distribution = GitHub Release ZIP like Android (ADR-0009/0024/0039). Source in new top-level `sdk-ios/` (design-index section). Independent version line from `0.1.0`. Tag `ios-vX.Y.Z` runs an iOS release workflow: Swift package source ZIP (with `Package.swift`), SHA-256, provenance attestation. Host adds the unzipped local package; an independent consumer app verifies it. Owner: Maven Central and remote SwiftPM are deferred and done together later. CocoaPods and XCFramework also deferred.
- 2026-10-26 Q8: Swift wire DTOs from the pinned openapi-generator `swift6`, models only, `internal`, into `generated/swift`; existing drift check covers it. Must use Foundation `Codable` only (zero deps). iOS tests read shared `fixtures/sdk-wire` and `fixtures/validation` for byte parity with Android. Fallback (first ticket decides, ADR): hand-written `Codable` checked by the same fixtures if the output needs a runtime or gets oneOf wrong. Apple swift-openapi-generator rejected (runtime deps). Tracking plan gets a Swift output in `generate.mjs` (ADR-0021 parity).
- 2026-10-26 Q9: first-release gates = (1) `ios-test` macOS job: Simulator build + unit tests under TSan; (2) public API check: committed `.swiftinterface` (library evolution) in `sdk-ios/api/`, diffed; (3) zero external dependency check in `check-repo-rules.sh`; (4) independent consumer app Simulator build from the unzipped package; (5) iOS version constant vs tag check. Xcode steps in `verify-contract.sh` run locally only when `xcodebuild` exists (else skip with a message); CI always runs them. Deferred: size budget and host cost (measure first, like ADR-0020 → 0023), physical device. Owner asked for parallel research on more production gates (vendor CI + senior iOS code quality) before finalizing.
- 2026-10-27 Q9 additions (owner accepted the bundle; research `.scratch/next-scope/ios-vendor-ci-gates.md`, `ios-apple-rules-and-quality.md`): (1) `PrivacyInfo.xcprivacy` as package resource, `NSPrivacyTracking=false`; `check-repo-rules.sh` greps SDK source for required-reason APIs (`systemUptime`, `mach_absolute_time`, `statvfs`, `volumeAvailableCapacity*`, `UserDefaults`, file `creationDate`/`modificationDate`) and fails when one is not declared. (2) `swift format` strict incl. `AllPublicDeclarationsHaveDocumentation`. (3) warnings-as-errors in CI only. (4) separate ASan+UBSan run. (5) `xcodebuild analyze`; CodeQL adds Swift (ADR-0032). (6) no `privacy: .public` in `sdk-ios` (grep). (7) app-only first release: public entry points `@available(iOSApplicationExtension, unavailable)`. (8) design rules: SQLite only on an actor with a custom `SerialExecutor` over a dedicated serial queue; re-check state after every `await`; `@unchecked Sendable` needs an ADR naming its invariant. Q9 correction: `.swiftinterface` only in a check build, not shipped (library evolution not needed for source distribution). Rejected: test retry, coverage floor, other-platform matrix. Risk: iOS 15 Simulator runtime may be missing on GitHub runners; first CI ticket checks; fallback = build at deployment target 15 + test on oldest available runtime.
- 2026-10-27 No disk-space API on iOS: Android does not use one either (`storageAvailable` = queue readable, `Results.kt:238`), so no `NSPrivacyAccessedAPICategoryDiskSpace`.
- 2026-10-27 Q10: query responses (event list, event detail) carry required `sdkPlatform` (server always fills it; additive per ADR-0007 tolerant responses). New optional query parameter `sdkPlatform` (`android|ios`) on every endpoint that takes `installationId` (`/v1/events`, `/v1/event-counts/by-name`, `by-time`, `by-plan-status`) and on `/v1/client-report-counts`; client report counts group by `(sdkPlatform, sdkVersion)`. Dashboard shows platform in list and detail and adds a platform filter to the shared filter set. Owner asked for the filter (recommendation was display only). Server deploys before Dashboard (strict parameters, ADR-0007).
- 2026-10-27 Q11: one SwiftUI app `compatibility/consumer-ios` = consumer + demo. It uses the SDK only as the unzipped local package; screens: product view, add to cart, simulated purchase, with tracking plan Swift output; endpoint = local Compose server. Cloud demo wiring is out of scope. CI builds it in Debug and Release (Release = `-O`, whole-module, dead stripping: the iOS form of the host release-build check that consumer-android does with R8, ADR-0009 item 6-7).
- 2026-10-27 Q12a: missing `sdkPlatform` stays `android` (not `unknown`). Wire compatibility is the same either way; `android` keeps old Android events in the `android` filter and kill-switch key, and needs no response-only enum value. Rule: every SDK from now on must send `sdkPlatform`, enforced by SDK wire fixture tests. Owner: record in an ADR.
- 2026-10-27 Q12: order = (1) contract `sdkPlatform` → (2) server: V4, default `android`, `(platform, version)` kill switch, filters → (3) Dashboard display + filter → (4) Android SDK 0.4.0 sends `sdkPlatform`, released only after (2) is deployed → (5) iOS SDK, built in parallel with 1-3, released only after (2) is deployed. Note: "deployed" includes the cloud demo server (ADR-0043) when a released SDK points at it.
- 2026-10-27 Q13: this scope includes (a) `scripts/simulator-durability.sh` (local only, `xcrun simctl`): kill during store/send, restart, update install, uninstall+install (new installation ID), opt-out, offline; pass = no loss, no server duplicate, queue state matches (ADR-0011/0029 criteria); backup restore and full disk are known limits on Simulator. (b) measurement: SDK size (consumer Release arm64 with/without SDK, unsigned), Simulator host cost (`initialize()`/`track()` main-thread time, cold start, memory), then a size budget CI gate from that measurement (measure ticket before gate ticket, ADR-0020 → 0023). Deferred: physical iPhone measurement (needs owner device, Apple Developer account, signing; like ADR-0042).
- 2026-10-27 Q14: privacy manifest collected data = `NSPrivacyCollectedDataTypeDeviceID` (installation ID) and `NSPrivacyCollectedDataTypeProductInteraction` (business events); both Linked=false, Tracking=false, purpose `NSPrivacyCollectedDataTypePurposeAnalytics`. The integration guide tells hosts to declare other data types they put in event properties.
- 2026-10-27 Q15 (from Claude review of PR #237): wire corpus per SDK (`fixtures/sdk-wire/android/`, `ios/`), each byte-locked; server parses both; same-name cases compared by JSON value (numbers by value, `sdkPlatform`/`sdkVersion` excluded). Byte parity rejected (number spelling such as Kotlin `1.0E-7` differs). Rejected: iOS compares by value only against the Android corpus (no iOS byte regression). Android corpus moves in ticket 04.
