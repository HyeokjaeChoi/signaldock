# SignalDock v0.4.0

Fourth tagged release of the Android SDK. License: Apache-2.0 ([LICENSE](../../LICENSE)). The public API of the SDK is the same, and the runtime dependency tree is the same. This release has two breaking behavior changes for an app that works with 0.3.0 ([versioning policy](../versioning.md): a 0.x minor can break when the changelog lists it): an event within 24 bytes of the 16 KiB limit is now rejected, and delivery needs a server with `sdkPlatform` support. See [Breaking changes](#breaking-changes) and [Upgrading from 0.3.0](#upgrading-from-030). The [changelog](../../CHANGELOG.md) lists the breaking changes under "Changed" and the new features under "Added".

The iOS SDK has its own release, `ios-v0.1.0` ([notes](ios-v0.1.0.md)). Both releases follow one rule: deploy the server first ([ADR-0046](../adr/0046-sdk-platform-field.md) decision 8).

## What is included

- The Maven repository ZIP `signaldock-sdk-android-0.4.0-maven.zip` and its `.sha256` file. The coordinate is `local.signaldock:sdk-android:0.4.0`. Maven Central is not used. See [Add the SDK to an app](../../README.md#add-the-sdk-to-an-app) and [ADR-0009](../adr/0009-maven-zip-and-consumer-app.md).
- A build provenance attestation for the ZIP ([ADR-0039](../adr/0039-release-provenance-attestation.md)).
- The source of the Android SDK, the iOS SDK, the server, the Dashboard, the demo app, the consumer apps, and the measurement harnesses, as in the tagged commit. See the [repository guide](../../README.md#repository-guide).

Verify the download from the folder that holds both files:

```sh
shasum -a 256 -c signaldock-sdk-android-0.4.0-maven.zip.sha256
```

Verify the attestation (GitHub CLI 2.102.0 or newer; older versions have attestation check flaws):

```sh
gh attestation verify signaldock-sdk-android-0.4.0-maven.zip --repo HyeokjaeChoi/signaldock \
  --signer-workflow HyeokjaeChoi/signaldock/.github/workflows/release.yml
```

The command must exit 0 (it prints `Verification succeeded!` in a terminal). The attestation shows that the release workflow of this repository built the ZIP. It does not show that the code is free of defects.

Requirements of the AAR did not change: `compileSdk` 36 or newer, `minSdk` 24 or newer, Kotlin 2.2 or newer, AGP 9.x ([README](../../README.md#add-the-sdk-to-an-app)).

## Breaking changes

- **Delivery needs a server with `sdkPlatform` support.** A server without it answers `UNKNOWN_FIELD`, and the SDK holds its queue. Deploy the server first.
- **`EVENT_TOO_LARGE` 24 bytes earlier.** `track()` returns `Invalid(EVENT_TOO_LARGE)` for an event within 24 bytes of the 16 KiB limit. 0.3.0 accepted the same input.

## What changed in the SDK

No public API change: `git diff v0.3.0 -- sdk/sdk-android/api` is empty. No runtime dependency change: `git diff v0.3.0 -- sdk/sdk-android/dependencies` is empty.

- **The SDK sends `sdkPlatform: "android"`.** Every event and every client report carries the field ([ADR-0046](../adr/0046-sdk-platform-field.md)). A server without `sdkPlatform` support rejects the field with `UNKNOWN_FIELD`, and the SDK holds its queue.
- **Events queued by 0.3.0** keep their stored bytes ([ADR-0006](../adr/0006-sdk-delivery-decisions.md) decision 3). They go without the field, and the server stores them as `android`.
- **24 bytes less room for host properties.** The field adds 24 bytes (`,"sdkPlatform":"android"`) to every event. An event that was within 24 bytes of the 16 KiB event limit in 0.3.0 now returns `EVENT_TOO_LARGE`.
- The SDK wire corpus moved to `fixtures/sdk-wire/android/` ([ADR-0047](../adr/0047-ios-sdk.md) D10). Its test, like the server `SdkWireCorpusTest`, fails when an event has no `sdkPlatform`.

## What changed in the server and the build

- **`sdkPlatform` support.** Migration `V4` adds the column. A missing field defaults to `android`. An unknown value gets a per-item rejection. The kill switch blocks by `platform:version` (an old item in `SIGNALDOCK_BLOCKED_SDK_VERSIONS` without a prefix means `android`). Five query endpoints accept the filter `sdkPlatform`. Client report counts group by platform and version ([ADR-0046](../adr/0046-sdk-platform-field.md)).
- **Migration cost.** `V4` adds a column with a constant default (no table rewrite) and a CHECK constraint. The CHECK scans `events` once under an exclusive lock inside the Flyway run. The server starts only after Flyway, so the cost is start-up delay. Estimate, not measured: a few seconds per million rows. Plan a restart window for very large tables.
- **Dashboard.** The Dashboard shows the platform in the event list, the event detail, the shared filter, and the "Dropped events" card ([ADR-0046](../adr/0046-sdk-platform-field.md) decision 7, PR #249).
- **Cloud demo infrastructure.** `infra/` (Terraform, host nginx, Compose override, VM scripts), the `demo-deploy` workflow, and `scripts/demo-seed.py` ([ADR-0043](../adr/0043-cloud-demo-hosting-and-deploy.md) to [ADR-0045](../adr/0045-cloud-demo-host-and-container-hardening.md)). No SDK change.
- **Fixes.** The server accepts the shortest round-trip text of a subnormal double (`5e-324`, as Swift writes it) as well as the Java text; normal doubles are unchanged ([ADR-0027](../adr/0027-request-400-contract-only.md), PR #259). The Dashboard image upgrades `brotli-libs` (CVE-2026-111497) and `curl` and `libcurl` (CVE-2026-92392). The server retries the Flyway connect at start. `scripts/demo-seed.py` and the demo reset have smaller fixes. See the [changelog](../../CHANGELOG.md).

## Upgrading from 0.3.0

1. **Deploy the server and the Dashboard that support `sdkPlatform` first.** This includes the cloud demo server when the app points at it. Read the migration cost above.
2. Change the version: `implementation("local.signaldock:sdk-android:0.4.0")`. No code change and no recompile-only change is needed.
3. Check events that are close to the 16 KiB limit (see "Breaking changes").

If you set `SIGNALDOCK_BLOCKED_SDK_VERSIONS`, old items keep their meaning (`android`). Use `ios:X.Y.Z` to block an iOS version.

Events collected after the update, and client reports, carry `sdkVersion` `0.4.0`. Events queued by 0.3.0 keep the `sdkVersion` they were collected with (spec 3, "Common information").

## What was verified

The commands and results are in the release pull request and in the records of the iOS SDK tickets ([`.scratch/ios-sdk/issues/`](../../.scratch/ios-sdk/issues/)). Summary:

- On the release branch (2026-10-29, JDK 21, `ANDROID_HOME` set): `scripts/check-repo-rules.sh` exit 0; `scripts/release.sh 0.4.0` (builds the ZIP, builds the consumer app from it as an R8 release, writes `dist/` and the `.sha256`; it does not tag or publish) exit 0; `sdk/gradlew -p sdk :sdk-android:testDebugUnitTest :sdk-android:apiCheck :sdk-android:dependencyGuard` exit 0 (169 SDK unit test cases, 0 failures).
- No change to the public API dump and the dependency baseline against `v0.3.0` (the two `git diff` commands above; `apiCheck` and `dependencyGuard` pass).
- The server and the SDK wire corpus agree: `SdkWireCorpusTest` fails on an event with no `sdkPlatform` ([ADR-0046](../adr/0046-sdk-platform-field.md), [ADR-0047](../adr/0047-ios-sdk.md) D10).

The numbers in the older release notes are local environment records, not an SLA.

## What was not verified

- The attestation. Run the command above after the release workflow succeeds and record the result in [issue 19 of the iOS SDK work](../../.scratch/ios-sdk/issues/19-release-android-0.4.0-ios-0.1.0.md).
- A physical device with the 0.4.0 SDK. The device records in the repository ran with 0.2.0 and 0.3.0 ([README, Limitations](../../README.md#limitations)).
- The upgrade of a large `events` table by `V4`. The start-up delay is an estimate.
- Release signing and Play distribution. The consumer app uses the debug key ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md)).
- A consumer on a Kotlin version other than the AGP 9.4.1 default (2.2.10), or on AGP 8.x ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md)).
- A host app that adds `kotlinx-serialization` 1.11.0 to its own compile classpath ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md)).
- The full server measurement matrix (216 runs, Q133).
- Public internet operation. The stack is local only; the cloud demo is a demo ([README, Limitations](../../README.md#limitations)).
