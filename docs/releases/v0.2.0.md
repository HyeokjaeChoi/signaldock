# SignalDock v0.2.0

Second tagged release. License: Apache-2.0 ([LICENSE](../../LICENSE)). This release has changes that need action when you upgrade from 0.1.0. Read [Upgrading from 0.1.0](#upgrading-from-010) first. The SDK is before 1.0, so a MINOR release can break an app. The breaking changes are listed under "Changed" in the [changelog](../../CHANGELOG.md) ([versioning policy](../versioning.md)).

## What is included

- The Maven repository ZIP `signaldock-sdk-android-0.2.0-maven.zip` and its `.sha256` file. The coordinate is `local.signaldock:sdk-android:0.2.0`. Maven Central is not used. See [Add the SDK to an app](../../README.md#add-the-sdk-to-an-app) and [ADR-0009](../adr/0009-maven-zip-and-consumer-app.md).
- The source of the Android SDK, the server, the Dashboard, the demo app, the consumer app, and the measurement harnesses, as in the tagged commit. See the [repository guide](../../README.md#repository-guide).

Verify the download from the folder that holds both files:

```sh
shasum -a 256 -c signaldock-sdk-android-0.2.0-maven.zip.sha256
```

Requirements of the AAR did not change: `compileSdk` 36 or newer, `minSdk` 24 or newer, Kotlin 2.2 or newer, AGP 9.x ([README](../../README.md#add-the-sdk-to-an-app)). The runtime `kotlin-stdlib` is 2.3.20 and the compile one is 2.2.21. This is expected ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md), PR #157).

## What changed in the SDK

- **Opt-out.** `SignalDock.setOptOut(Boolean)`, `isOptedOut()`, and `clearQueue()` are new. While opted out, `track()` stores nothing and returns the new `TrackResult.OptedOut`. Queued events stay and are still sent unless you call `clearQueue()`. The state is kept across restarts ([ADR-0034](../adr/0034-sdk-opt-out.md), PR #159).
- **HTTPS enforcement.** `SignalDock.initialize` returns `InvalidConfiguration` for an endpoint that is not `https`. The new `SignalDockConfig.allowInsecureEndpoint` (default `false`) allows `http` only. Reason: a cleartext endpoint sends the collection key in plain text ([ADR-0035](../adr/0035-sdk-https-enforcement.md), PR #160).
- **Client reports.** The SDK counts the events it dropped (`queue_full`, `storage_error`, `invalid_event`, `event_too_large`, `server_rejected`) and sends the counts to the new `POST /v1/client-reports`, at most once per send cycle. The Room database is now schema 3, with migrations 1 to 2 and 2 to 3, so queued events survive the update ([ADR-0036](../adr/0036-sdk-client-reports.md), PR #161; [ADR-0025](../adr/0025-sdk-clock-jump.md), PR #109 for the migration 1 to 2).
- **Deprecation headers.** The SDK reads `Deprecation` and `Sunset` headers, logs one warning per process, and shows the dates in `Diagnostics.contractDeprecation`. A `Retry-After` HTTP-date with trailing text is now ignored. The server does not send these headers yet ([ADR-0030](../adr/0030-sdk-contract-deprecation-warning.md), PR #123).
- **Clock jump.** The stored retry wait is clamped when the device clock moves back ([ADR-0025](../adr/0025-sdk-clock-jump.md), PR #109).
- **Dependency baseline.** `sdk/sdk-android/dependencies/` lists the resolved runtime and compile classpaths. A change without a new baseline fails `scripts/verify-contract.sh` ([ADR-0033](../adr/0033-sdk-dependency-baseline.md), PR #147). Gap: the baseline is a record. It does not stop a consumer from resolving other versions.

## What changed in the server and the Dashboard

- The server has two new endpoints: `POST /v1/client-reports` and `GET /v1/client-report-counts`. The contract version stays 1. The change is compatible. Migration `V3__create_client_reports.sql` stores one row per entry, with no installation ID. The Dashboard shows a "Dropped events" card ([ADR-0036](../adr/0036-sdk-client-reports.md), PR #161).
- Optional tracking plan status for stored events ([ADR-0022](../adr/0022-server-tracking-plan-status.md), PR #101).
- `/ready` database check and a restart policy in Compose ([ADR-0026](../adr/0026-server-readiness-and-restart.md), PR #110).

## Upgrading from 0.1.0

1. **Recompile your app.** The JVM constructor and `copy` signatures of `SignalDockConfig` changed, because of the new `allowInsecureEndpoint` parameter. The change is source compatible. It is not binary compatible ([ADR-0035](../adr/0035-sdk-https-enforcement.md), PR #160).
2. **Handle `TrackResult.OptedOut`.** A `when` expression over `TrackResult` with no `else` branch does not compile until it has a branch for `OptedOut` ([ADR-0034](../adr/0034-sdk-opt-out.md), PR #159).
3. **Check your endpoint.** An `http://` endpoint now gives `InvalidConfiguration`. Use `https://`. For a local test, set `allowInsecureEndpoint = true`. The demo and consumer apps do this for `http://` endpoints ([ADR-0035](../adr/0035-sdk-https-enforcement.md), PR #160).
4. **Update the server for client reports.** An old server answers 404 to `POST /v1/client-reports`. The SDK then discards the report and keeps sending events as before. You lose the drop counts, not events ([ADR-0036](../adr/0036-sdk-client-reports.md), PR #161). Deploy the new server, run migration `V3`, then update the apps.
5. **Expect a database migration.** On the first start, the SDK moves Room schema 1 to 3. The queue and retry state are kept ([ADR-0025](../adr/0025-sdk-clock-jump.md), [ADR-0036](../adr/0036-sdk-client-reports.md)).
6. **Expect a new `sdkVersion` value.** Events and reports now carry `sdkVersion` `0.2.0`. Server data by SDK version shows it (spec 3, "Common information").

## What was verified

The commands and results are in the release pull request. Summary:

- SDK unit tests, `apiCheck`, `dependencyGuard`, `scripts/release.sh 0.2.0`, `scripts/release.sh 0.2.0 --check`, `scripts/verify-consumer.sh`, and `scripts/check-size-budget.sh` ran on the release branch before the tag.
- The Room migration from 1 to 3 has tests in the SDK ([ADR-0025](../adr/0025-sdk-clock-jump.md), [ADR-0036](../adr/0036-sdk-client-reports.md)).

The numbers are local environment records, not an SLA.

## What was not verified

- Physical devices. SDK measurement ran on emulators only ([README, Limitations](../../README.md#limitations)).
- A new device measurement of 0.2.0. The 0.1.0 results in `perf/sdk-results/` are not repeated for 0.2.0 ([ADR-0014](../adr/0014-sdk-device-measurement-harness.md)).
- Release signing and Play distribution. The consumer app uses the debug key ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md)).
- A consumer on a Kotlin version other than the AGP 9.3.3 default (2.2.10), or on AGP 8.x ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md)).
- A host app that adds `kotlinx-serialization` 1.11.0 to its own compile classpath ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md), PR #157).
- Public internet operation. The stack is local only ([README, Limitations](../../README.md#limitations)).
