# SignalDock v0.3.0

Third tagged release. License: Apache-2.0 ([LICENSE](../../LICENSE)). This release has no breaking change from 0.2.0. The public API of the SDK is the same, and the runtime dependency tree is the same. See [Upgrading from 0.2.0](#upgrading-from-020). The changes are listed under "Added" in the [changelog](../../CHANGELOG.md) ([versioning policy](../versioning.md)).

## What is included

- The Maven repository ZIP `signaldock-sdk-android-0.3.0-maven.zip` and its `.sha256` file. The coordinate is `local.signaldock:sdk-android:0.3.0`. Maven Central is not used. See [Add the SDK to an app](../../README.md#add-the-sdk-to-an-app) and [ADR-0009](../adr/0009-maven-zip-and-consumer-app.md).
- A build provenance attestation for the ZIP. This is the first release that has one ([ADR-0039](../adr/0039-release-provenance-attestation.md)).
- The source of the Android SDK, the server, the Dashboard, the demo app, the consumer app, and the measurement harnesses, as in the tagged commit. See the [repository guide](../../README.md#repository-guide).

Verify the download from the folder that holds both files:

```sh
shasum -a 256 -c signaldock-sdk-android-0.3.0-maven.zip.sha256
```

Verify the attestation (GitHub CLI 2.102.0 or newer; older versions have attestation check flaws):

```sh
gh attestation verify signaldock-sdk-android-0.3.0-maven.zip --repo HyeokjaeChoi/signaldock \
  --signer-workflow HyeokjaeChoi/signaldock/.github/workflows/release.yml
```

The command must print `Verification succeeded!`. The attestation shows that the release workflow of this repository built the ZIP. It does not show that the code is free of defects.

Requirements of the AAR did not change: `compileSdk` 36 or newer, `minSdk` 24 or newer, Kotlin 2.2 or newer, AGP 9.x ([README](../../README.md#add-the-sdk-to-an-app)).

## What changed in the SDK

No public API change: `git diff v0.2.0 -- sdk/sdk-android/api` is empty. No runtime dependency change: `git diff v0.2.0 -- sdk/sdk-android/dependencies` is empty.

- **Baseline Profile.** The AAR ships `baseline-prof.txt` (519 rules for `local.signaldock.**`) for `initialize()`, `track()`, the Room queue, and the sender. The AGP of the host app merges it into the app profile. The host needs no change. On one API 37 emulator, the p50 of the SDK startup work was 28 % and 53 % lower than with no compilation in two runs, and 1 % lower in a third run. The SDK rules alone gave no result outside the noise. The modules `sdk/profile-app` and `sdk/baseline-profile` generate and measure the profile. They are not published ([ADR-0040](../adr/0040-sdk-baseline-profile.md)).

## What changed in the server and the build

- **Collection kill switch.** The operator can block events by exact name (`SIGNALDOCK_BLOCKED_EVENTS`) and by exact event `sdkVersion` (`SIGNALDOCK_BLOCKED_SDK_VERSIONS`). A blocked event gets the existing per-item rejection with the new code `COLLECTION_BLOCKED`, so the SDK deletes it and counts `server_rejected`. `SIGNALDOCK_INGEST_SHED=true` makes the two ingest routes answer 503 with `Retry-After` (`SIGNALDOCK_INGEST_SHED_RETRY_AFTER_SECONDS`, default 1). The server reads the variables at start. By default, nothing is blocked. The server cannot stop collection on the device ([ADR-0037](../adr/0037-server-collection-kill-switch.md)).
- **Gradle dependency verification.** Each of the four Gradle builds has `gradle/verification-metadata.xml` with SHA-256 checksums. A dependency file that is not listed, or that differs, fails the build. `scripts/update-gradle-verification.sh` rewrites the files. Gap: the checksums are trust on first use. No product code and no published POM changed ([ADR-0038](../adr/0038-gradle-dependency-verification.md)).
- **Provenance attestation.** The `publish` job of the release workflow signs the attestation before it creates the release ([ADR-0039](../adr/0039-release-provenance-attestation.md)).

## Upgrading from 0.2.0

Change the version only: `implementation("local.signaldock:sdk-android:0.3.0")`. No recompile-only change, no code change, and no database migration is needed. The server change is optional: the kill switch has no effect until you set its environment variables.

Events collected after the update, and client reports, carry `sdkVersion` `0.3.0`. Events queued by 0.2.0 keep the `sdkVersion` they were collected with (spec 3, "Common information").

## What was verified

The commands and results are in the release pull request. Summary:

- SDK unit tests, `scripts/release.sh 0.3.0`, and `scripts/check-repo-rules.sh` ran on the release branch before the tag.
- `apiCheck` and `dependencyGuard` pass with no baseline change (issue 70).
- The SDK instrumented tests ran once on a physical device: Samsung SM-F766N (Galaxy Z Flip7), Android 16 (API 36). 49 tests finished, 0 failed, 16 skipped because they are phase tests that need `-e phase` ([issue 73](../../.scratch/signaldock/issues/73-real-device-test-galaxy-z-flip7.md)).
- The demo app ran on the same phone: one event was sent, stored by the server, and confirmed in the Diagnostics tab ([issue 74](../../.scratch/signaldock/issues/74-phone-demo-install-record.md)). The SDK version of that build was 0.2.0.
- The Baseline Profile effect was measured on one API 37 emulator (numbers above, [ADR-0040](../adr/0040-sdk-baseline-profile.md)).

The numbers are local environment records, not an SLA.

## What was not verified

- The attestation. The `gh attestation verify` command has not run on a released ZIP. This release workflow produces the first attestation. Run the command after the workflow succeeds and record the result in [issue 78](../../.scratch/signaldock/issues/78-release-v0-3-0.md).
- SDK measurement on a physical device, and `scripts/device-durability.sh` on a physical device. The Baseline Profile gain is not proved: it ran on one emulator, and the SDK rules alone gave no result outside the noise ([README, Limitations](../../README.md#limitations)).
- The instrumented tests on a physical device ran on the 0.2.0 code, not on a 0.3.0 build.
- Release signing and Play distribution. The consumer app uses the debug key ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md)).
- A consumer on a Kotlin version other than the AGP 9.3.3 default (2.2.10), or on AGP 8.x ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md)).
- A host app that adds `kotlinx-serialization` 1.11.0 to its own compile classpath ([ADR-0009](../adr/0009-maven-zip-and-consumer-app.md), PR #157).
- The full server measurement matrix (216 runs, Q133).
- Public internet operation. The stack is local only ([README, Limitations](../../README.md#limitations)).
