# Failure modes and effects analysis

Status: written 2026-10-15. Format follows [Azure failure mode analysis](https://learn.microsoft.com/en-us/azure/well-architected/reliability/failure-mode-analysis).
Severity and Likelihood are my ratings (High, Medium, Low) for this local project. They are not measured.
"Gap" means that I found no mitigation or no test in the repo. I did not invent one.

Short paths in the Evidence column:
- `SDK:` = `sdk/sdk-android/src/test/kotlin/local/signaldock/` (JVM tests, Robolectric)
- `DEV:` = `sdk/sdk-android/src/androidTest/kotlin/local/signaldock/device/` (emulator tests; [ADR-0011](../adr/0011-sdk-device-test-harness.md))
- `SRV:` = `server/app/src/test/kotlin/local/signaldock/server/`
- `PER:` = `server/persistence/src/test/kotlin/local/signaldock/persistence/`
- `Sender` = `sdk/sdk-android/src/main/kotlin/local/signaldock/internal/delivery/Sender.kt`
- `Database` = `server/persistence/src/main/kotlin/local/signaldock/persistence/Database.kt`

## Gaps found

1. No test or guard for a wall-clock jump in the SDK retry time (row 6).
2. No server-side rate limit and no `429` (row 5).
3. No test with the database stopped; `/health` does not check the DB; no restart policy (row 11).
4. A request-level 400 holds the entire queue; no bisecting of a batch (row 10).
5. No separate ingest and query budgets (row 17).
6. `Retry-After` is a fixed 1 second (row 4).
7. Power-loss durability and a real full disk are untested (rows 2, 8, 9).
8. No alerting or metrics endpoint anywhere (rows 4, 11).
9. Rejected options for Room and the Worker path are not recorded ([design-review.md](design-review.md)).
