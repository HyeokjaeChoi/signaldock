# SDK storage and collection decisions (issue 03)

The design sources leave these points open (spec section 8 "C. Small modules and local execution", section 9 items 1, 5 and 6: "fix exact signatures during implementation"). This ADR records the choices made in issue 03. It adds no new product behavior.

## Decisions

1. **KSP pin: 2.3.12.** KSP has no 2.4.x release as of 2026-10-09. Since KSP 2.3 the version is independent of the Kotlin version. 2.3.12 is the latest stable release. It was build-verified with Kotlin 2.4.21, AGP 8.13.2, Gradle 8.14.5 and Room 2.8.5 (Room schema export and DAO generation ran). Pinned in `gradle/libs.versions.toml`.
2. **Module layout.** `sdk/sdk-android` is the one publication module (Q86). `sdk/` stays the independent Gradle build (Q89). Generated Kotlin models are compiled in as a source directory (`../../generated/kotlin/src/main/kotlin`) and used for the event transport JSON, so the size limits are measured on the real contract bytes. **Contract-area change:** `scripts/codegen.sh` now passes `nonPublicApi=true` to the Kotlin generator, so the generated models are `internal` and transport DTOs are not in the SDK's public API (architecture "Components"; spec section 3). `generated/kotlin` was regenerated; generated TypeScript is unchanged. Each consumer compiles the generated sources into its own module (SDK, contract-check), so `internal` works; a consumer that uses them from a separate module would need another approach. `PublicApiTest` asserts that every top-level `org.openapitools` class in the compiled SDK is Kotlin-`internal`.
3. **Queue row = one event's transport JSON; size = the event as sent.** The `events` table stores `payloadJson` (the generated `EventIngest` serialized by kotlinx.serialization), `sizeBytes`, `eventId` (unique), `installationId`, `contractVersion` and `createdAtMillis`. `sizeBytes` comes from one canonical function, `singleEventRequestBytes` (`internal/Transport.kt`): the UTF-8 bytes of a generated `BatchIngestRequest` holding this one event, with wrapper, installationId, common fields and escaping (spec section 4). The 16 KiB event limit and the 16 MiB queue total both use it; the total counts the wrapper once per event, which is conservative. The sender (issue 04) must reuse this function. Tests check exactly 16 KiB passes and 16 KiB + 1 fails.
4. **Whitespace set for names and keys (Q64): one explicit Unicode White_Space list**, identical to the server's (server issue 02): U+0009..U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000..U+200A, U+2028, U+2029, U+202F, U+205F, U+3000. Kotlin `Char.isWhitespace()` is not used because it differs (for example it includes U+001C..U+001F). U+200B, U+FEFF and U+180E are not in the set and are accepted. The SDK test iterates the whole set. The contract and fixtures should still list this set.
5. **Public API shape.** `SignalDock.initialize(context, config): InitResult` (suspend), `track(name) { property(...) }: TrackResult` (suspend), `diagnostics(): Diagnostics` (suspend). Property overloads: `String`, `Boolean`, `Int`, `Long`, `Double`. There is no `Float` overload, because widening `Float` to `Double` changes the value. Times in diagnostics are epoch milliseconds (`Long`): `java.time` needs API 26 and minSdk is 24. Timeouts use `kotlin.time.Duration`.
6. **Corrupt installation ID file.** If the stored value is not a UUIDv4, the SDK logs a WARN and writes a new ID. Stored events keep the installation ID from collection time (ADR-0001). An unreadable or unwritable file is a storage failure (`InitError.StorageFailure`).
7. **Diagnostics storage.** Tables `rejections` (last 100, no payload or name) and `retry_state` (single row: failure count, next attempt time, last ACK counts) exist in schema version 1. `retry_state` also holds a typed, content-free last delivery error (`DeliveryErrorKind`, optional HTTP status, time; spec section 6 "Demo and diagnostics"). Schema stays at version 1, because no SDK is released yet and no migration is needed; this ADR is the record. `diagnostics()` reads usage, retry state and rejections in one `@Transaction`, so it is one snapshot. Issue 04 writes `retry_state`. The exported schema is committed under `sdk/sdk-android/schemas/`.
8. **JVM tests.** Robolectric 4.17 with `sdk=36` on JDK 21, and real Room on the Robolectric file system. No emulator. Test JVMs get `--add-exports=java.base/jdk.internal.access=ALL-UNNAMED`, because without it the Robolectric tests fail on JDK 21 ("Failed to interact with raw FileDescriptor internals"). Verified by `sdk/gradlew -p sdk :sdk-android:testDebugUnitTest :sdk-android:assembleRelease --no-daemon` (35 tests, 0 failures).

   History: until issue 11 (2026-10-11) the tests ran at `sdk=35`, because SDK 36 needs JDK 21 and the pin was JDK 17.

9. **R8 and Kotlin 2.4 metadata.** Kotlin 2.4 needs R8 9.1.29 or newer ([AGP, D8, and R8 versions required for Kotlin versions](https://developer.android.com/build/kotlin-support)). The SDK builds with AGP 9.3.3, which bundles its own R8. **Verified in issue 06 (2026-10-12): AGP 9.3.3 bundles R8 9.3.28.** The header of `mapping.txt` from the independent consumer app's minified release build reads `# compiler: R8`, `# compiler_version: 9.3.28` (ADR-0009). That build printed no Kotlin-metadata warning ("An error occurred when parsing kotlin metadata", see [steamclock/steamclog-android#137](https://github.com/steamclock/steamclog-android/issues/137)), and the minified APK initialized the SDK and had an event accepted by the server on an API 37 emulator. `sdk-android` itself does not enable minification; the AAR carries unshrunk classes and R8 runs in the consumer app's build. The SDK code does not use Kotlin reflection.

   History: before issue 11 (2026-10-11) the SDK built with AGP 8.13.2, whose bundled R8 8.13.19 predates Kotlin 2.4. The AGP 9 migration was then rejected in TOOLCHAIN.md. Issue 11 reversed that decision.

## Not covered here

Delivery, ACK application by the sender, WorkManager scheduling and foreground triggers (issue 04). Backup exclusion on a real device and a real process restart are not verified by these JVM tests.
