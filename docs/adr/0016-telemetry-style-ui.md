# Telemetry-style redesign of the Dashboard and the benchmark report (issue 28)

Spec Q139 and Q140 (2026-10-13) fix the scope and the pattern set: presentation only, no new API, no new view. The sources of the patterns are in `.scratch/signaldock-portfolio/issue-28-design-references.md`. This ADR records how the code follows them and the decisions that Q139 and Q140 leave open. The user can change these decisions.

## Decisions

1. **Shared design tokens in `web-shared/theme/` (follows ADR-0015, Q137).** Plain files with no `package.json`. Both pages import them by relative path (`import "../../web-shared/theme/tokens.css"`).
   - `tokens.css`: CSS custom properties. Surfaces and lines (`--bg`, `--surface`, `--surface-raised`, `--surface-sunken`, `--input-bg`, `--line`, `--line-strong`), text (`--fg`, `--fg-muted`), brand and status (`--accent`, `--ok`, `--warn`, `--bad` and soft variants), charts (`--c1` to `--c3`, `--chart-axis`, `--chart-grid`, `--chart-cursor`, `--band-baseline`, `--band-overload`, `--band-recovery`), spacing (`--space-1` to `--space-7`, a 4 px grid), radius (`--radius-sm` 6 px, `--radius-md` 12 px, `--radius-pill`), type (`--font-sans`, `--font-mono`, `--text-xs` to `--text-kpi`), and depth and motion (`--shadow-pop`, `--ease-out`, `--dur-fast`, `--focus-ring`). The dark values are on `:root`; `:root[data-theme="light"]` overrides them.
   - `base.css`: element styles that read the tokens (controls, segmented switch, badge, card, KPI, table, focus ring, scrollbar and selection colors). Page layout stays in each page's `styles.css`.
   - `theme.ts`, `react.ts`, `index.ts`: theme choice and the `useTheme()` hook. `chart.ts`: shared Recharts props (`AXIS`, `GRID`, `TOOLTIP`, `LEGEND`, `SERIES`, `SERIES_DASH`) that point at the tokens, so a theme switch restyles the charts without a re-render. It has no JSX, for the reason in ADR-0015 decision 3.
   - Both builds stay separate (ADR-0008, ADR-0013). The Dashboard Dockerfile already copies `web-shared/`.

2. **Theme: dark by default, a light switch, nothing else decides (Q140).** `<html data-theme="dark|light">` selects the token set. The choice is saved in `localStorage` under the key `signaldock.theme` (`dark` or `light`; an unknown value is ignored). Every storage access is in try/catch, so the page works when storage is blocked and the choice then lasts for the page load. `prefers-color-scheme` is not read. An inline script in each `index.html` sets `light` before the first paint, so a saved light choice does not flash dark; a test checks that both files use the key of `theme.ts`. The switch is a labelled group of two buttons with `aria-pressed` (labels through `t()`), next to the language switch.

3. **Status is a dot plus a word.** The per-query status line shows its badge only when that query is not `live` (the KPI card already shows the overall state), so a retry, a stop, a first load, and the `Not updating` page state stay visible. `.badge` shows a shape and the word (`Live`, `Retrying`, `Stopped`, `pass`, `fail`, `invalid`, `pilot: not counted`). The shapes differ (circle, square, triangle), so the state is also readable without color. Line series differ by dash pattern (`SERIES_DASH`); every chart with more than one series has a legend (the single-series Dashboard charts have none, their card title names the series), and the Dashboard name chart prints the count at the end of each bar. The overload bands carry the phase name as text.

4. **Contrast.** Text, muted text, accent, and status colors are at least 4.5:1 on every surface token in both themes; the three chart series are at least 3:1. `web-shared/theme/contrast.test.ts` reads `tokens.css` and computes the WCAG ratios, also for status text on its soft badge background and for text on the selected row. The focus ring (`:focus-visible`, 2 px `--accent`) is on every control. Motion is limited to hover, press, and color changes (140 ms, `ease-out`); focus does not animate; smooth scrolling runs only without `prefers-reduced-motion: reduce`.

5. **Controls.** A `select` has `appearance: none` and a chevron from the token `--chevron` (one data-URI value per theme, because a data URI cannot read `--fg-muted`; `padding-right: 2rem`; `option` colors from the tokens). With `(pointer: coarse)` controls, Copy buttons, and event-name links are at least 44 px high (issue 29; Copy was 36 px). Desktop rows keep their height. In the event table, Copy buttons have no border or background until the row is hovered or has focus (`(hover: hover)` devices only; touch and keyboard focus always show them), and event-name links are underlined only on hover and focus. At 720 px or less, Period and Sort share a row and Apply, Clear, and Refresh stay in one row. Press scale is off with `prefers-reduced-motion: reduce`.

6. **Layout breakpoints.** A CSS variable cannot be used in a media query, so the values are written in the CSS files and named here: 1100 px (Dashboard: the event table and the detail stack; report: the table of contents becomes a sticky bar) and 720 px (Dashboard: the toolbar stops being sticky and its controls fill the width; both: one column of charts and a single-column header). Chart grids use `auto-fit` with a minimum of 22 rem (Dashboard) and 26 rem (report).

7. **Dashboard (Q140).**
   - KPI cards derive from the three queries the page already runs (`dashboard/src/kpi.ts`, unit-tested): events received today (sum of the by-time buckets that start on today's date in the project timezone; it follows the filters in force and the card says so; `No data` when the shown period has no bucket for today, or when the server reports another timezone than the project timezone, because its day buckets then start on other dates); last receipt (newest `receivedAt` of the first page sorted newest first; for other sorts and pages the card says `No data` and names the condition, because no other page holds the latest receipt); query state (one badge for the three queries: stopped on a contract error (Q108) wins over retrying (Q109), then loading before the first success, then live, or `Not updating` when the list shows a page after the first, because that page does not poll (Q77); a failure of that page is also `Not updating`, not retrying, because it retries only when the user asks; a refresh after a success keeps showing live, so the badge does not flash on every 5-second poll); top event name (largest count in the by-name result).
   - One sticky toolbar holds period, sort, the three exact filters, apply, clear, and refresh. The tests' accessible names and the apply and clear behavior are unchanged. The page scroll offset (`scroll-padding-top`) follows the rendered toolbar height through a `ResizeObserver`, because the toolbar wraps and grows with error text. The per-query status lines (last success, errors, retry, reload) stay as they were; the badge shows only when the query is not live (decision 3).
   - Split layout: the event table on the left, the existing details view on the right, no navigation. An empty right pane shows a hint. The Dashboard has no URL state for the selected event, so there is no deep link to keep. The selected row is marked with `aria-current` and a left edge, not by color alone.
   - A per-name trend is not derivable: the by-time counts are not split by name, and Q139 allows no new request or API. The counts view keeps its bars and shows the count at the end of each bar.

8. **Benchmark report (Q140).**
   - The KPI strip shows the verdict, p95, max, 503 share, dropped iterations, and run count. Every card names its source, because the report never averages percentiles of different runs (Q133): the verdict is the worst verdict of all runs ("3 of 3 runs pass"); p95 and max are the collection endpoint of the selected run of the runs table (measurement phase); the 503 share is the collection endpoint in the overload phase of the last overload run; dropped iterations are summed over all runs (a count, not a percentile); run count is the number of runs and overload runs. Each card is a link to its section (`#runs`, `#overload`, `#latency`); a card whose section is not on the page (no overload run) is plain content.
   - A sticky table of contents (Runs, Overload, SDK, Latency) is a rail beside the content and a bar on narrow screens; the section in view gets `aria-current="location"`.
   - Overload charts show baseline, overload, and recovery bands (`ReferenceArea`), each with its phase name. Bands only mark the phases; they filter nothing. Round 2: only the overload band is tinted (about 11 % `--bad`); baseline and recovery are transparent (labels stay), because a green recovery tint hid the green 200 bars.
- Round 2 decisions: links keep a faint underline at rest (full on hover and focus); Copy is ghost at rest on hover devices and bordered on touch, with a reserved width; invalid inputs get a `--bad` border and focus; chart legends keep series order, single-series legends are removed, time axes start at 0 with whole-second ticks and a unit label; table scroll wrappers are `position: relative` so `.sr-only` status text cannot widen the page.
   - The x-axis labels of the SDK charts overlapped. The charts with long run names (SDK track, SDK rate, and the latency per run charts) are now horizontal bars with the names on the y-axis.
   - The report CSS moved from `index.html` to `perf/report/src/styles.css` (Vite inlines it into the bundle, so the page still opens from `file://`).

9. **Accessibility and layout follow-up (issue 29).** Presentation only (Q139).
   - Every table has a name: a visually hidden `<caption className="sr-only">` with the text of the heading above it (Dashboard event table and property table; report Runs, per-phase overload, SDK, latency, and statements tables; the throttling table already had a visible caption).
   - Each page starts with a skip link (`.skip-link`, visible on focus) to `<main id="main" tabIndex={-1}>`; the text is `app.skip`.
   - Opening an event moves focus to the details heading (`tabIndex={-1}`); Close returns focus to the event link that opened it (the link is found by event id, so a poll that re-renders the row does not lose it). If the row is no longer on the page, focus stays where the browser puts it.
   - The `" | "` separators of the status line are `aria-hidden`.
   - `.pane-scroll` and the detail pane use `overscroll-behavior: contain` and `dvh` heights with a `vh` fallback. The sticky toolbar has an opaque `--surface` background and no `backdrop-filter`.
   - Report latency charts: the y-axis shows the run id; the tooltip title keeps the full "pool, repetition, pilot (run id)" text. The Runs table run id button has no min-height or block padding on a fine pointer, so its rows match the other tables.
   - Decisions 5 changed (Copy and event-name link 44 px on touch). Not changed then: the style choices that issue 30 held (decided in decision 10).

10. **Visual style follow-up (issue 30, Q141 to Q147).** Presentation only (Q139). The user decided each point; this entry records how the code follows.
   - Shape (Q141): `--radius-md` 12 px and `--radius-sm` 6 px stay. Color tokens (Q143) stay; only `--text-kpi` changes (1.625 rem to 1.5 rem).
   - Structure (Q142): the Dashboard toolbar is a flat bar (`--bg` background, bottom border, no radius), still sticky and opaque (issue 29). A `.table-wrap` or `pre` inside a `.card` has no border (`.card .table-wrap, .card pre` in `base.css`); tables keep the sunken header and the sideways scroll shadows.
   - KPI cards (Q144): value 1.5 rem, padding `--space-2` `--space-3`. Every card has a sub line from data the page already has. Dashboard: "Received today" shows `Shown period: N` (sum of all by-time buckets, `periodTotal` in `kpi.ts`; `, filtered` is added when a filter is in force; before the first result it shows the old filter hint); "Query state" without a success yet shows `No successful query yet`; "Top event" without a name shows `No event names in the shown period`. Report: cards without a run or an overload run show `No run data` or `No overload run`.
   - Run id (Q145): the report Runs table run id is a `button.link` (the Dashboard event-name style); the selected run is bold through `aria-pressed`. The 44 px touch target stays.
   - Timestamps (Q146): the event table shows `receivedAt` in a `<time class="stamp" datetime>` element, monospace, with the date part in `--fg-muted` (`formatDateTimeParts` in `web-shared/i18n`). The details view keeps plain text (it is a definition list, not a table).
   - Mobile filters (Q147): at 720 px or less the three exact filters render inside `<details class="more-filters">` with the summary `More filters`; period, sort, and the buttons stay outside. It is open while a filter is applied and closes after Clear; the user can toggle it. This breakpoint is also read in JavaScript (`useNarrow` in `App.tsx`, `matchMedia`), because a wide screen must not render a disclosure at all (no reliable CSS way to force a `<details>` open). Both values are in decision 6's 720 px. The summary is 44 px on touch.

11. **Not changed.** The query API, polling, retry, and contract-error behavior (ADR-0007, Q107 to Q109), the views, the message catalog rules (ADR-0015), the dependencies and pins. No A/B run compare (Q139: a new view).

## Verification

`cd dashboard && npm test` runs the unit tests of the KPI derivations (`kpi.test.ts`), the theme module (`web-shared/theme/theme.test.ts`: default, saved choice, storage that throws, the key in both `index.html` files), the token contrast (`web-shared/theme/contrast.test.ts`), and the render tests (theme switch label, `data-theme`, saved key; KPI cards without an extra request). The scan of ADR-0015 decision 5 covers the new components and strings. Screenshots in both languages and both themes are in `.scratch/signaldock-portfolio/evidence/28-*.png`.

## Limits

- The light theme is a switch, not a system setting: a user with a light OS and no saved choice sees dark first.
- The contrast test covers token pairs, not every state in a browser.
- The report page still has no render test (ADR-0015 "Not done").
