# CI device tests and APK size budget (issue 40)

ADR-0011 decision 10 kept the instrumented tests out of CI, and ADR-0020 measured the SDK cost only on a local emulator. This ADR records how CI now runs the device tests and guards the APK size. It adds no product behavior and changes no SDK code. The choices are implementer decisions that the user can change.

## Decisions

1. **Tool: `reactivecircus/android-emulator-runner` v2.38.0.** It is what okhttp and many Android projects use on `ubuntu-latest`: it installs the system image, creates the AVD, boots it, runs the script, and stops it. The README names `@v2` as the current major. The action is pinned by commit SHA with the tag in a comment, like `actions/checkout` in the same file. `actions/cache` v6.1.0 and `actions/upload-artifact` v7.0.2 are pinned the same way. Gradle's own cache is not added (no other job has one).
2. **One API level: 34, `google_apis`, `x86_64`.** `ubuntu-latest` has KVM, which only runs x86 images; the local arm64 images of ADR-0011 cannot run there. API 34 is a stable, widely used release between the two local runs (API 24 and API 37). The tests need no Google services, but `google_apis` is the target of the local images, so the system apps match. API 34 was chosen over 35 or 37 because the images are mature and the 16 KB page-size variants are not involved. One level keeps the job short; a matrix with API 24 would double the time and is not done. The tests did not run on API 34 before this change. They are known to pass on API 24 and API 37 (issue 20), so the first CI run is the proof for API 34.
3. **What runs.** `sdk/gradlew -p sdk :sdk-android:connectedDebugAndroidTest --no-daemon`: the 26 `@Test` methods of `sdk-android` (`src/androidTest` and `src/measure`). The tests need no server and no root: the server is a MockWebServer on the device (ADR-0011 decision 2), and the one shell use is `logcat -d` of the test's own process. The 10 methods of `DurabilityPhases` and `MeasurePhases` skip themselves with `assumeTrue` when no `-e phase` is given (ADR-0011 decision 4), so they show as skipped. Nothing is excluded. The process-boundary cases (`am force-stop`, reinstall, backup and restore) stay in `scripts/device-durability.sh`, which is local and emulator-only. Measurements stay local (ADR-0014, ADR-0018, ADR-0020).
4. **KVM and the AVD cache.** The job writes the udev rule `KERNEL=="kvm", GROUP="kvm", MODE="0666"` (the runner action README adds `OPTIONS+="static_node=kvm"`; that is kept) and runs `udevadm trigger --name-match=kvm`. `actions/cache` stores `~/.android/avd/*` and `~/.android/adb*` under the key `avd-34-google_apis-x86_64-v1`. On a cache miss, a first runner step boots the AVD once and saves a snapshot (`force-avd-creation: false`, snapshot saving on). The test step always runs with `-no-snapshot-save`, so it starts from the cached snapshot and does not change it. Change the key (for example `v2`) when the API level, target, or architecture changes, or when the cache must be rebuilt. Emulator options: `-no-window -gpu swiftshader_indirect -noaudio -no-boot-anim`. Animations are turned off for the test run. The job has `timeout-minutes: 30`; the test report folder is uploaded when the job fails.
5. **Toolchain.** The job uses `scripts/setup-toolchain.sh` like the other jobs and exports `JAVA_HOME` through `GITHUB_ENV`, because the emulator action runs each script line in its own shell. The runner's Android SDK (`ANDROID_HOME`) is used; the action adds the system image.
6. **Size budget: `scripts/check-size-budget.sh`, job `size-budget`.** It builds the Maven ZIP, then the consumer app (`compatibility/consumer-android`, R8 release) with the SDK and with `-Psignaldock.sdk=false` (ADR-0020), compares the APK file bytes, prints both sizes and the delta, and exits 1 when the delta is above the budget. No emulator, no new dependency. The job is separate from `consumer-r8` so that both run in parallel; it builds the ZIP a second time, which costs a few minutes of CI time and no extra logic in `verify-consumer.sh`.
7. **Budget value: 700,000 bytes.** The measured delta is 616,829 bytes (ADR-0020, macOS run). A local run of the script on the current code gave 617,077 bytes (the small difference is the build, not the method). 700,000 is about 13 % above, a round number that leaves room for a different R8 or zip result on the Linux runner and for small SDK growth, and does not allow a large new dependency. The number lives only in `BUDGET_BYTES` at the top of the script. **To raise it on purpose,** change that constant in the same PR that adds the size, and update `CHANGELOG.md` and this section (new value, the measured delta, and the reason) in that PR. Do not raise it only to make the job pass. If the first CI run on Linux is outside the budget because of the platform and not the code, record the measured Linux value here and set the budget from it.

## Limits

- GitHub Actions cannot run here. The workflow was checked by YAML parsing only (`actionlint` is not installed on the author's machine). Whether the emulator boots, the 26 tests pass on API 34 x86_64, the AVD cache hits on the second run, and the Linux APK delta is inside the budget can be shown only by CI.
- The local run of `connectedDebugAndroidTest` on the running API 37 emulator (Android 17) did not pass: 16 tests failed in `createSdk` with `IOException: cannot create SDK directory`, because the app's data directory `/data/user/0/local.signaldock.test` did not exist after install (`run-as` reported "No such file or directory"). The failure is in the emulator state, not in the CI setup, but it was not investigated further, so the tests are not shown to pass on any emulator in this issue.
- The device tests are timing-sensitive (Worker, retry waits) and a software-rendered emulator on a shared runner is slower than a local one. A flaky failure is treated as a finding about the test, not retried automatically.
- API 34 only. API 24 (minSdk) is not run in CI; it was run locally (issue 20).
- The size budget measures the APK file size of a tiny consumer app, not what a large app pays after sharing libraries (ADR-0020 limits).
