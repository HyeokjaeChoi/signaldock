## Verified defects

### 1. P1: verification directly executes a non-executable generator script

Location: `scripts/verify-contract.sh:29`; `scripts/codegen.sh:1` (Git mode).

The exact Git tree gives `scripts/codegen.sh` mode `100644`. The verifier invokes it directly, rather than through `bash`. On a normal POSIX checkout, this fails with permission denied before the drift check, even when Java and the generator JAR are installed. `verify-contract.sh` itself is now `100755`; this is a separate remaining permission defect. Set the generator's executable bit or invoke it with `bash`.

### 2. P2: the mutable baseline is a change gate, not a compatibility gate

Location: `scripts/verify-contract.sh:37-40`.

`oasdiff diff -o` fails on any reported change. The pinned [oasdiff v1.33.0 implementation](https://github.com/oasdiff/oasdiff/blob/322d7ae815e5fb80f415bd4e8ef16d4b30cd8bdf/internal/diff.go) confirms this flag means `fail-on-diff`; it does not classify breaking changes. The script tells authors to update the baseline in the same PR. Thus, removing a required response field and copying the new contract into the baseline makes this stage compare equal documents and pass. Keeping the baseline instead rejects compatible additions too. Neither path enforces ADR-0002 / spec Q65. Preserve a prior release or prior-schema fixture and run a breaking-change check against it. Keep deliberate snapshot updates separate from that comparison. The two target files are currently byte-identical; no existing released-client break is claimed.

### 3. P2: a valid `__proto__` property key is silently lost in TypeScript conversion

Location: `generated/typescript/runtime.ts:413-417`; callers: `generated/typescript/models/EventIngest.ts:97,117`.

`mapValues` writes keys into `{}` with `result[key] = ...`. For a JSON-parsed properties object containing an own `"__proto__": "sku-42"` entry, this assignment reaches the inherited `__proto__` setter. A scalar value does not create an own property, so conversion drops the entry. The contract allows this nonempty property key. This contradicts preservation of event properties. Use an own-property-safe map and preserve the fix through generation inputs. This is static JavaScript reasoning, not an executed reproduction or a prototype-pollution claim.

## Numeric contract gap and verification limits

- `openapi/contract-v1.yaml:98-102` permits an unrestricted number. Spec line 58 requires integers within ±(2^53−1), including integer values sent through the Double path, and finite Double decimals. The generated Kotlin decoder at `EventIngestPropertiesValue.kt:90-93` constructs BigDecimal without those checks; the TypeScript converter at `EventIngestPropertiesValue.ts:31-32,51-52` passes numbers through. For example, `9007199254740992` is outside the agreed integer domain but is not excluded by this schema. Record the numeric policy in the contract and validate it in the planned adapters. Spec section 9 explicitly permits adapters, so this does **not** establish that a product SDK/server validator is broken; those validators are outside this skeleton.
- The five Kotlin tests cover request/ACK/error round trips and null/nested rejection. They do not check numeric limits, overflow, additional response fields, or `__proto__` preservation. The checked-in request fixture uses `1.0` and `0.0`; it does not contain `1e0` or negative zero despite broader historical execution descriptions. TypeScript verification is type checking only, not a runtime round trip.
